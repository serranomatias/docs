Receive a JSON **POST** after call analysis. Configure the voice agent’s outgoing URL in **Advanced → Post-call** and publish. This contract covers browser tests, phone calls, campaigns, and widgets.

## When delivery happens

<Steps>
  <Step title="The conversation ends">Ending the call does not immediately provide its analyzed result.</Step>
  <Step title="Analysis becomes available">ContactShip prepares summary, extracted fields, transcript, and call result. If the agent has evaluations, delivery can wait for their results.</Step>
  <Step title="Your receiver accepts the event">ContactShip posts the body below. Persist accepted work and return HTTP 2xx within 30 seconds; process longer workflows asynchronously.</Step>
</Steps>

## Payload structure

The top-level body is `{ "data": { ... } }`. It has no required `event` or webhook event ID. A test call can have an associated contact; the presence of a contact controls the extra fields.

| Situation | `data.contact` | Extra call fields | `data.campaign` |
|---|---|---|---|
| Web call without a contact | Omitted | Omitted | `{}` |
| Web call with an associated contact | Included | Included; phone values may be empty | `{}` |
| Registered phone call with a contact | Included | Included | `{}` unless a campaign call |
| Campaign call | Included when available | Included when associated | Campaign details |

Extra call fields are `call_result`, `from_number`, `to_number`, and `call_additional_data`. See [Call types](/en/calls/call-types) for each origin and the distinction between type, state, and result.

## Field reference

Expand an object to inspect its fields. Optional context can be omitted; some stored values can be `null` or empty.

<ResponseField name="data.agent" type="object">
  Agent associated with the call.
  <Expandable title="data.agent">
    <ResponseField name="agent_id" type="string">
      ContactShip agent ID.
    </ResponseField>

    <ResponseField name="name" type="string">
      Agent name.
    </ResponseField>

    <ResponseField name="language" type="string">
      Agent language.
    </ResponseField>

    <ResponseField name="voice" type="string">
      Voice identifier.
    </ResponseField>

  </Expandable>
</ResponseField>

<ResponseField name="data.organization" type="object">
  Organization context when available. Contains `name`, `email`, and `country`; no organization ID.
</ResponseField>

<ResponseField name="data.call" type="object">
  Call result. Handle a missing block if context could not be retrieved.
  <Expandable title="data.call">
    <ResponseField name="call_id" type="string">
      ContactShip call ID. Match it to `data.call_id` from the call-creation response.
    </ResponseField>

    <ResponseField name="call_type" type="string">
      Origin of the call: `test_web_call`, `test_phone_call`, `api_call`, `platform_contact_call`, `campaign_call`, `inbound_call`, `widget_web_call`, or `web_call`.
    </ResponseField>

    <ResponseField name="call_status" type="string">
      At this stage normally `ended` or `failed`. An unanswered call can be `ended`; check `call_result` when present.
    </ResponseField>

    <ResponseField name="duration" type="number | string">
      Seconds. Normalize with `Number(value)` and validate before calculations.
    </ResponseField>

    <ResponseField name="start_timestamp" type="number">
      Unix time in milliseconds; `0` can indicate unavailable data.
    </ResponseField>

    <ResponseField name="end_timestamp" type="number">
      Unix time in milliseconds; `0` can indicate unavailable data.
    </ResponseField>

    <ResponseField name="disconnection_reason" type="string">
      Why the call disconnected, for example `user_hangup`, `call_transfer`, `max_duration_reached`, `no_answer`, or `failed`.
    </ResponseField>

    <ResponseField name="recording_url" type="string">
      Recording URL when available. Empty does not mean a recording exists.
    </ResponseField>

    <ResponseField name="transcript" type="string">
      Plain conversation text; may be empty.
    </ResponseField>

    <ResponseField name="transcript_object" type="object[]">
      Structured transcript messages, including role, content, and word timing when available.
    </ResponseField>

    <ResponseField name="transcript_with_tool_calls" type="object[]">
      Transcript including tool activity when available. Entries can have different shapes.
    </ResponseField>

    <ResponseField name="call_analysis" type="object">
      Post-call analysis and optional evaluation results.
      <Expandable title="call_analysis">
        <ResponseField name="call_summary" type="string">
          Conversation summary.
        </ResponseField>

        <ResponseField name="user_sentiment" type="string">
          Detected sentiment when available.
        </ResponseField>

        <ResponseField name="custom_analysis_data" type="object">
          Your configured extraction fields. Define their keys and types in the voice agent’s post-call settings; a missing key is not a false value.
        </ResponseField>

        <ResponseField name="call_successful" type="boolean">
          Whether analysis judged the call’s goal successful. This does not mean every downstream action succeeded.
        </ResponseField>

        <ResponseField name="in_voicemail" type="boolean">
          Whether voicemail was detected.
        </ResponseField>

        <ResponseField name="evaluation_results" type="object[]">
          Present when configured evaluations produced results. An absent array can mean no criteria or unavailable results. `unknown` means the criterion was evaluated but could not be determined.
          <Expandable title="evaluation_results">
            <ResponseField name="key" type="string">
              Evaluation key.
            </ResponseField>

            <ResponseField name="name" type="string">
              Evaluation name.
            </ResponseField>

            <ResponseField name="result" type="string">
              `success`, `failure`, or `unknown`.
            </ResponseField>

            <ResponseField name="rationale" type="string">
              Explanation of the result.
            </ResponseField>

            <ResponseField name="quote" type="string">
              Supporting transcript excerpt; may be empty.
            </ResponseField>

            <ResponseField name="score" type="number | null">
              Score when provided; otherwise `null`.
            </ResponseField>

          </Expandable>
        </ResponseField>

      </Expandable>
    </ResponseField>

    <ResponseField name="call_result" type="string">
      Only in the contact-associated branch. Examples: `answered`, `no_answer`, `voicemail`, `failed`. Omission is not evidence that the call was answered.
    </ResponseField>

    <ResponseField name="from_number" type="string | null">
      Only in the contact-associated branch. Source number from the call record; can be empty for web calls.
    </ResponseField>

    <ResponseField name="to_number" type="string | null">
      Only in the contact-associated branch. Destination number from the call record; can be empty for web calls.
    </ResponseField>

    <ResponseField name="call_additional_data" type="object | null">
      Only in the contact-associated branch. Additional data saved for this call-contact relationship; usually `{}` when none exists. Not an automatic copy of every prompt variable or metadata value.
    </ResponseField>

  </Expandable>
</ResponseField>

<ResponseField name="data.contact" type="object">
  Present when a contact is associated and its context is available.
  <Expandable title="data.contact">
    <ResponseField name="contact_id" type="string">
      ContactShip contact ID.
    </ResponseField>

    <ResponseField name="full_name" type="string">
      Contact name.
    </ResponseField>

    <ResponseField name="phone_number" type="string | null">
      Contact phone; may be empty for web registrations.
    </ResponseField>

    <ResponseField name="email" type="string | null">
      Contact email when available.
    </ResponseField>

    <ResponseField name="country" type="string | null">
      Contact country when available.
    </ResponseField>

    <ResponseField name="additional_data" type="object | array | null">
      Properties stored on the contact, separate from per-call additional data.
    </ResponseField>

    <ResponseField name="call_attempts" type="number">
      Attempts from the campaign-contact relationship; defaults to `0` outside campaigns. Not the contact’s lifetime call count.
    </ResponseField>

    <ResponseField name="call_status" type="string">
      Campaign-contact status, when available. Separate from `data.call.call_status`.
    </ResponseField>

    <ResponseField name="contact_data" type="object | null">
      Data from the campaign-contact relationship, when available.
    </ResponseField>

  </Expandable>
</ResponseField>

<ResponseField name="data.campaign" type="object">
  Campaign context for `campaign_call`. Normally `{}` for other types; can be omitted if unavailable.
  <Expandable title="data.campaign">
    <ResponseField name="name" type="string">
      Campaign name.
    </ResponseField>

    <ResponseField name="description" type="string">
      Campaign description.
    </ResponseField>

    <ResponseField name="start_at" type="string">
      Campaign start time when available.
    </ResponseField>

    <ResponseField name="status" type="string">
      Campaign status.
    </ResponseField>

  </Expandable>
</ResponseField>

## Correlation and missing data

- Store the call ID from creation. This webhook does not forward `metadata`, a separate event ID, `direction`, organization ID, campaign ID, call price, or agent version as dedicated fields.
- Use `data.call.call_analysis.custom_analysis_data` for fields you configure in **Post-call**. Use your own ID mapping to recover CRM context.
- Missing `evaluation_results` can mean no evaluations were assigned or no results became available. `unknown` is an evaluation result, not a missing evaluation.
- A call without a recorded call row may have no final webhook. This can affect inbound calls that never connect.
- For an unanswered call, use `call_result` when present. `call_status: "ended"` alone does not mean someone answered.

## Delivery and retries

The sender uses `Content-Type: application/json`, a 30-second timeout, and accepts HTTP **2xx**. It can follow up to three redirects. Queue retries and manual retries can deliver the same call again.

Use durable processing state keyed by call ID and action. Persist accepted work before acknowledging it, retry failed actions independently, and avoid duplicating completed external operations. A generic HTTP success response does not prove your business action finished.

The sender does not add the lead-routing `x-contactship-signature` header. Do not reuse another webhook’s signing contract. Keep API keys on your server; an API key is not automatically sent to your webhook URL.

## Inspect an actual delivery

Open **Calls → Webhooks** and select the event. Compare destination, attempts, response, and raw data with your receiver. The event ID shown in that screen helps support investigate; it is not automatically present in the HTTP body.

The current voice editor has no sample-payload test button. Publish the URL and make a controlled test call. Receiver workflows can perform real actions during tests.
